# Postgres scripts

Everything the database needs, as plain SQL, so it can be reviewed, applied by a DBA, or run on a
platform that does not use the Node toolchain. Drizzle migrations in `db/migrations` remain the
source of truth for the application; `schema.sql` is generated from them.

| File                        | Purpose                                                                                                                                 | Run as    |
| --------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- | --------- |
| `../init/01-extensions.sql` | `vector` and `pgcrypto` extensions (Docker runs it on first start)                                                                      | superuser |
| `00_roles.sql`              | Database roles: owner, app, ingest, analytics, with their default `app.scope`                                                           | superuser |
| `schema.sql`                | Full DDL: schemas `raw`, `derived`, `access`, `ingest`; tables, indexes, RLS policies, functions, views. Generated by `npm run db:ddl`. | owner     |
| `01_grants.sql`             | Grants per role, including default privileges for future tables                                                                         | owner     |
| `02_rls_check.sql`          | Smoke test that row-level security denies by default and scopes by RM and team                                                          | any       |

## Apply from scratch

```bash
psql "$ADMIN_URL" -v ON_ERROR_STOP=1 -f db/init/01-extensions.sql
psql "$ADMIN_URL" -v ON_ERROR_STOP=1 -f db/sql/00_roles.sql
psql "$OWNER_URL" -v ON_ERROR_STOP=1 -f db/sql/schema.sql
psql "$OWNER_URL" -v ON_ERROR_STOP=1 -f db/sql/01_grants.sql
psql "$OWNER_URL" -f db/sql/02_rls_check.sql
```

Then load data with `npm run db:seed` (full load from a dataset folder) or through the ingest module
(`npm run ingest:batch -- <dir>` for message files, or the Kafka consumer in `apps/ingest`).

## Row-level security in one paragraph

Every client-owned table has a policy `access.can_see(client_id)` with `FORCE ROW LEVEL SECURITY`,
so even the owner sees nothing unless the connection declares a scope in the `app.scope` setting:
`all` for loaders and the analytics service, `own` with `app.rm_id` for an RM, `team` with
`app.team_id` for a team head, `none` for an unauthenticated connection. Entitlement comes from
`raw.rm_assignments` (dated, roles primary / secondary / checker / cover) through
`access.entitled_clients()`. The API sets these per request after verifying the caller's token.
Tables whose `client_id` may be null (audit events, LLM traces, quality issues, change log) show
their book-level rows to any authenticated scope.

## Regenerating

```bash
npm run db:generate   # after editing db/src/schema
npm run db:migrate    # apply to the local database
npm run db:ddl        # refresh db/sql/schema.sql
```
